# Step 5 — Assets

## Inventory and provenance log — every file, every time

| Field | Notes |
|---|---|
| File | Name and format |
| Source | Which folder/kit/message it arrived in |
| Mark owner | Whose IP it is — property, partner, photographer |
| Permission | What the kit explicitly grants. "Sent to us" is NOT a licence. |
| Read? | Whether you actually opened it. Unread is recorded, not guessed. |

If the kit states no usage terms, record **"no terms stated"** and flag it
for a human before anything third-party ships.

## The property's promotional graphic is not a cover image

A partner-reveal graphic is a designed ad for the deal — logos on a treated
background, in the property's brand system, with its own headline. Using it
as a Playbook cover makes Playbook look like a channel of the property.
Same rule `publish-sourced-article` carries for company press releases.

It IS useful as: a source for the marks, confirmation of the commercial
name, and a reference for what the property is emphasising.

## Output a spec for the breaking-news graphic

Do not leave the designer to guess. Specify:

- **Canvas** per channel (1080×1080 feed, 1080×1920 story, 1200×630 OG).
- **Crop**: what the focal point is, what must not be cut.
- **Lockup placement**: which marks, in what order, at what relative size,
  with what clear space. Both marks at equal optical weight for a
  partnership — a size imbalance implies a hierarchy the deal may not have.
- **Headline copy**: the exact words, in Playbook's voice, not the kit's.
- **Safe areas**: platform UI overlap on stories, caption crop on feed.
- **What NOT to use**: name the assets deliberately excluded and why.
